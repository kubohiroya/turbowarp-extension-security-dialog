# 0.15.0 リリース候補

対象: [#97](https://github.com/kubohiroya/turbowarp-extension-security-dialog/issues/97)、[#106](https://github.com/kubohiroya/turbowarp-extension-security-dialog/issues/106)。ブランチ: `chore/release/0.15.0`、base: `31ab732`。担当: kubohiroya。

## 公開する変更

- ギャラリーの画像情報を使い、カタログとURL・ハッシュを照合してPlusファミリーバッジを表示する（#117、#120）。画像や自己申告の名前から信頼・実行許可を付与しない。
- 公開拡張の取得・取消中にカタログ操作が競合することを防ぐ。追加前にnpmの正確な版やGitHub Releaseタグを選び直し、配布元へ戻れる（#118、#121）。
- `./react`へ`ExtensionDevelopment`を追加する。ホスト能力に従って開発sessionの接続・取消・停止・再開・解除と、最後の適用済みビルド、待機、build/runtime診断を表示する（#122）。ソース移動は適用ビルドと一致する検証可能な相対座標だけを任意のホストcallbackへ渡す。
- 開発検証用Loaderを0.16.2へ、Playwrightを1.65.1へ更新する（#116、#119）。実行時依存のmanifest 0.8.0は維持する。

## 受け入れ基準と公開順序

この候補ではパッケージの版とリリース記録だけを変更し、機能の追加修正を混ぜない。

1. 固定依存を使い、`pnpm run check`で型検査・全単体テスト・pack dry runを確認する。
2. 通常CIと同じ5ファイルのブラウザ検証をヘッドレスで確認する。Desktop checkoutを必要とする検証のskipは明記し、実製品の検証と区別する。
3. コミットされた候補のnpmアーカイブを作り、公開export・CSS・build-infoの版と完全SHA・`sourceState: commit`を照合する。テストやnode_modulesを配布しない。
4. ユーザー承認後にpush・PR作成し、CIと公開差分を再確認してSquash Mergeする。さらに承認された場合だけ、マージコミットへ`v0.15.0`を作成・pushする。
5. 既存Release workflowが再検証・pack・GitHub Release添付・OIDCによるnpm公開を行う。`latest`と`next`はいずれも0.15.0となる。公開後にregistryのintegrityとGitHub添付を照合する。
6. 公開済みアーカイブの実integrityでEditorのmanifestとlockfileを更新・検証する。そのEditorがmainへ入ってからDesktopのrenderer固定を更新・再ビルドする。

Editor／Desktopの固定更新は別差分であり、この候補には含めない。Editorの固定は調査時点でsecurity-dialog 0.14.3、Editor mainは`1e11679bf5ab67ebeb54d68ae4779a0235115c54`。Desktop mainのrenderer固定はEditor `6e8767a348f59ee5f3db4e1b023dc1ca4f869bbd`であり、更新時には再度リモートmainを確認する。

今回の候補作成は公開操作を実行する承認ではない。npm公開・Release作成を含む対象と操作列を提示して確認する。

## 残課題・切り戻し

版一覧と導入済み拡張の更新管理、GitHubソースビルド、ツール容量・進捗、全診断のビルド紐付け、製品のソース移動接続、OS／Loaderを含む確認回数の測定は残る。Issue #106の完了とは扱わない。Desktopの共有UIへの接続はPR #80でマージ済みだが、互換な共有版とEditor／rendererの固定更新までは旧表示を維持する。

公開前はこの版変更をrevertする。公開後は同じnpm版を置換せず、Editor依存とDesktop rendererを直前の検証済み固定へ戻して再ビルドする。必要な修正は新しい版で公開する。開発フォルダ・作品・最後の正常成果物は削除しない。
